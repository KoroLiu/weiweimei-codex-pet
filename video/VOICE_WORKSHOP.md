## 2. 审稿时，先做这六件事

1. **确定这一段想让观众知道什么。** Hook 让观众认识角色；Download 告诉他怎样拿到项目；Install 告诉他文件放哪。每段只完成一个主要目标。
2. **自己读一遍。** 遇到你自己也不愿说的长句，换成顺口的说法。例如“完成项目部署”换成“把我装进电脑里”。
3. **把重要内容说清楚。** 操作不能只剩梗；不要为了可爱省掉关键步骤。“选我”需搭配画面上的“维维美”。
4. **分开“说出来的”和“画面显示的”。** 字幕和画面可显示完整路径、菜单英文和文件名，声音可以说“画面上的目录”“这两个文件”。你也可以决定让她读文件名，但需要专门检查发音。
5. **适量用口语词。** “嘿”“啦”“一起看看”可以拉近距离；不用每句都加。“表情管够”可以保留或改得正式一些。
6. **核对真实功能。** 本片介绍九组动作。十六方向和鼠标视线跟随已取消，不作为功能或卖点；方向格保留是图集格式兼容。工作表情短暂播放的限制保留。

你可以直接改 [口播审核稿](SCRIPT_REVIEW.md)，或者给我“Showcase 改成……，其余保留”的修改清单。编辑器里的文档是审稿用；正式合成会使用 storyboard.json 的 say 字段，我会把你确定的稿同步进去。

## 3. 自己动手，具体改哪里

[storyboard.json](storyboard.json) 按七个场景排列：

- `say`：这一场景实际朗读的完整文本。改这里会改变声音。
- `cues[].text`：画面字幕。改这里只改变字幕内容。
- `displaySay`：普通审核稿，不含音素标注；与 say 同步修改。
- `cues[].voiceSentence`：从 0 开始，指出字幕属于第几个完整句子；增加句子时一并核对。
- Hook 的 `keepGreetingTogether`：短招呼一起生成，避免单独割开 Bang。
- `title`：场景名称。画面中的大标题还在 `src/scenes/`，不能只改这里就认为画面标题也变了。

当前自动化为了避免低显存自动切断句子，要求每个生成单元不超过 40 个字符，包括标点、英文和发音标注。完整场景可以有多句。这是工作流限制，不是模型最大字数；长句可重新安排，不必删除重要信息去凑长度。

JSON 的字段名、引号、逗号需要保留。只改引号里面的台词即可。Codex 在合成稿里保留英文并试用官方音素标注，字幕显示普通英文；Mini 在口播中读“迷你”。英文处理见第 9 节。

## 4. 怎样用标点调表达

| 操作 | 小例子 | 先听什么 |
| --- | --- | --- |
| 句号分开完整意思 | “嘿，我是维维美。接下来教你安装。” | 是否清楚，但没有被切成机械短句 |
| 逗号保留语意连接 | “下载压缩包，再解压。” | 是否有自然转折，是否连读太急 |
| 感叹号增加兴奋感 | “装好啦，我来陪你工作！” | 是否太夸张、是否影响清晰度 |
| 问号做邀请 | “想让我陪你用 Codex？” | 句尾是否像邀请，而不是机械念词 |
| 改措辞强调重点 | “要放进去的是整个文件夹。” | 重点是否听得出来 |

标点是给模型的线索，不是精确停顿时长。不要把“[停顿]”写进朗读文本，它可能被念出来。本轮脚本在完整句子间额外插入 160 毫秒，逗号处不拆。重音和音高由模型生成；本版 UI 没有逐字重音或音高编辑器。

## 5. 在官方 UI 里亲手试听

用 PowerShell 启动已有环境，无需新安装：

```powershell
& 'C:\IndexTTS\scripts\Start-IndexTTS.ps1'
```

打开终端显示的本机地址，默认 `http://127.0.0.1:7860`。启动后保留终端；结束试听后可以在终端 Ctrl+C 停止。不要同时启动多个合成实例。

1. 进入“预设管理”，刷新列表，选 **维维美_轻元气_090**，点“应用”；也可在音频生成页“从预设加载”。
2. 查看参考音频已经加载，情感方式为向量；开心 0.30、惊喜 0.05、权重 0.65、随机关闭。
3. **手动把语言设为 ZH，时长系数设为 0.94。** 090 是旧预设名，仍用于载入参考和情感；本轮没有另建官方 094 预设。官方预设不恢复语言、时长系数、稿件或种子。
4. 放入一个完整句子，或整段稿件做连续版，点“生成语音”。不要按字幕行拆成几个字。要复现本轮精确额外 160 毫秒，用脚本流程；UI 的 interval_silence 是模型分块之间的设置，不能理解成每个句号都插相同时长。
5. 先听有没有读对，再听语气。下载保留自己喜欢的 WAV；记录文字和参数，不要只凭文件名猜设置。
6. 想做对比时保留基准版本，再只改一个值。例如同一句对比 0.94 / 0.98；其余参数保持原样。
7. 自己的新实验用另一个预设名，例如“维维美_实验_开心035”。完整的已认可 profile 和试听原件仍保留。

UI 没有暴露本脚本的固定种子，因此界面同参数重复生成可能有细节差异。你要严格按这次完整配置复用时，让我用脚本即可。

## 6. 建议的试听顺序

| 顺序 | 你改什么 | 先试多少 | 什么时候才继续改 |
| --- | --- | --- | --- |
| 1 | 台词 | 一次只改一个场景 | 意思正确、口语顺畅 |
| 2 | 标点 | 同一句两个版本 | 自然、清楚，不靠刻意空白 |
| 3 | 速度 | 0.94 与 0.98 | 仍觉得句内太急时，后一档要求稍慢 |
| 4 | 开心 | 0.30 与 0.35 | 仍觉得不够活泼时 |
| 5 | 情感权重 | 0.65 与 0.70 | 想增强既定情绪时 |

这些是小幅实验起点，不是必须调整的标准。当前先审核 0.94 分句试听。不要同一次把速度、开心、权重、参考音频都换掉。temperature、top_p、top_k、num_beams 等高级生成项先保持已存值，只有出现具体问题时再排查。

先听动作展示的“完整句子分别生成 + 160 毫秒”和“整段生成，不额外加停顿”。分句也改变了句内表达，两者并非只差静音的严格对照。若两版都不舒服，增加空白未必能解决读稿腔，可改参考或降低情感强度做短样。

## 7. 把审核稿接回视频

最简单：把改好的文字或你喜欢的 WAV 发给我，我核对版本、替换音轨、测量时长、更新画面和字幕。

自己运行时，进入 video 文件夹，给每一版一个新的批次名：

```powershell
Set-Location -LiteralPath 'C:\codex project\codex pet\video'
powershell -NoProfile -File .\scripts\make-index-voiceover.ps1 -BatchName my-edit-v2
npm run sync-voiceover
npm run dev
```

合成使用 D:\Anaconda\envs\index-tts；官方权重仍在 C:\IndexTTS。中央原始音频、参数在 C:\IndexTTS\outputs\weiweimei\pet-intro\批次名；视频里的音轨副本在 public/voiceover/批次名。旧批次不会覆盖。

脚本按中央 profile 的 generationMode 选择整段或整句，durationFactor 调速度，sentencePauseMs 调额外句间空白；新实验另存配置。只改开场可加 `-Scene Hook`；改全局语速或情感应重生成全片。

场景长度和句子边界来自实测 WAV；同一句内部字幕页按文本长度估算，仍需试听修正，没有完成逐词识别。脚本同时输出与时间线等长的整片审核 WAV。字幕编辑写回 src/speech.tsx，再 sync 会重生成它：先保留修改，或把修正写回 voiceover-timing.json。声音与稿件审核通过后再导出定稿。

## 9. 英文不顺：先校正发音，不急着训练

当前模型支持英文与官方音素标注。此前使用“扣代克斯”会按中文音译读；本轮试用 `<Bang|B AE1 NG>` 和 `<Codex|K OW1 . D EH0 K S>`。Bang 的标注来自 CMU 词典；Codex 是本轮试验拼法，效果待试听。尖括号是合成指令，字幕仍用普通英文。

音素能约束读音，不能保证口音、词间连接或整句韵律自然。只给英文文字不会训练模型。先查拼写、发音和中英混读，必要时单独试英文短句。当前采用零样本声音复刻，不需要先训练角色模型。

来源：[IndexTTS 官方说明](https://github.com/index-tts/index-tts/blob/main/docs/README_zh.md)、[CMU 发音词典](https://raw.githubusercontent.com/cmusphinx/cmudict/master/cmudict.dict)。

## 10. 新参考怎样选

先找一两段 **5–12 秒** 的候选，这是本次选材的实用起点，不是模型硬性标准。选一个人、少音乐、无明显回声、清楚说完整自然的句子；避免截断词、只留尖叫大笑或拼接不同声线。

- **同角色的自然说话**：可换参考 B 做同稿试听；若有合适中文片段，更方便对照中文口音和节奏。
- **其他人的自然讲解**：可当你希望的节奏示范。直接换成声线参考可能改变角色声音，需明确用途。
- 日语原音仍可用来合成中文，但参考音不保证让模型逐处照搬停顿和语调。

给链接和时间段，再写“这里的句尾、节奏舒服”即可。保留原片段，按实际背景音乐决定是否提纯，避免过度处理损伤声线。
