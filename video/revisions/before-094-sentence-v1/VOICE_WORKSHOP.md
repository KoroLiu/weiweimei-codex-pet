# 你可以怎样修改口播稿和语气

本项目当前采用用户已认可的“维维美 · 轻元气 · 0.90 · 整段”。声音配置已定，视频台词仍是审核稿。先改内容，再试听，每次只改一个因素。

## 1. 当前基准，随时可以回到这里

| 项目 | 当前值 | 它影响什么 |
| --- | --- | --- |
| 参考 | B，日语原音 27.60–33.20 秒 | 主要决定声线 |
| 时长系数 | 0.90 | 整体速度；小于 1 更快，大于 1 更慢 |

## 2. 审稿时，先做这六件事

1. **确定这一段想让观众知道什么。** Hook 让观众认识角色；Download 告诉他怎样拿到项目；Install 告诉他文件放哪。每段只完成一个主要目标。
2. **自己读一遍。** 遇到你自己也不愿说的长句，换成顺口的说法。例如“完成项目部署”换成“把我装进电脑里”。
3. **把重要内容说清楚。** 操作不能只剩梗；不要为了可爱省掉关键步骤。“选我”需搭配画面上的“维维美”。
4. **分开“说出来的”和“画面显示的”。** 字幕和画面可显示完整路径、菜单英文和文件名，声音可以说“画面上的目录”“这两个文件”。你也可以决定让她读文件名，但需要专门检查发音。
5. **适量用口语词。** “嘿”“啦”“一起看看”可以拉近距离；不用每句都加。“表情管够”可以保留或改得正式一些。
6. **核对真实功能。** 九组动作、十六方向是素材；不要把它写成“持续跟随鼠标”或“任务多久，我就思考多久”。工作表情短暂播放的限制保留。

你可以直接改 [口播审核稿](SCRIPT_REVIEW.md)，或者给我“Showcase 改成……，其余保留”的修改清单。编辑器里的文档是审稿用；正式合成会使用 storyboard.json 的 say 字段，我会把你确定的稿同步进去。

## 3. 自己动手，具体改哪里

[storyboard.json](storyboard.json) 按七个场景排列：

- `say`：这一场景实际朗读的完整文本。改这里会改变声音。
- `cues[].text`：画面字幕。改这里只改变字幕内容。
- `title`：场景名称。画面中的大标题还在 `src/scenes/`，不能只改这里就认为画面标题也变了。

当前自动化为了保持整段生成，要求每个场景的 say 不超过 40 个字符。字符包括标点；英文按字母算。要增加内容时交给我增加场景或重新安排，不必自己删掉重要信息去凑长度。这是这套工作流的限制，不能理解为模型最多只能说 40 字。

JSON 的字段名、引号、逗号需要保留。只改引号里面的台词即可。产品正式名称在审稿文件里显示为 Codex / Mini；合成稿暂用“扣代克斯 / 迷你”帮助发音，你听完可以决定是否保留。

## 4. 怎样用标点调表达

| 操作 | 小例子 | 先听什么 |
| --- | --- | --- |
| 句号分开完整意思 | “嘿，我是维维美。接下来教你安装。” | 是否清楚，但没有被切成机械短句 |
| 逗号保留语意连接 | “下载压缩包，再解压。” | 是否有自然转折，是否连读太急 |
| 感叹号增加兴奋感 | “装好啦，我来陪你工作！” | 是否太夸张、是否影响清晰度 |
| 问号做邀请 | “想让我陪你用 Codex？” | 句尾是否像邀请，而不是机械念词 |
| 改措辞强调重点 | “要放进去的是整个文件夹。” | 重点是否听得出来 |

标点是给模型的线索，不是精确停顿时长。现在不往文本里写“[停顿]”、不增加固定静音，也不用一长串省略号去逼它停。重音和音高由模型生成；本版 UI 没有逐字重音或音高编辑器。

## 5. 在官方 UI 里亲手试听

用 PowerShell 启动已有环境，无需新安装：

```powershell
& 'C:\IndexTTS\scripts\Start-IndexTTS.ps1'
```

打开终端显示的本机地址，默认 `http://127.0.0.1:7860`。启动后保留终端；结束试听后可以在终端 Ctrl+C 停止。不要同时启动多个合成实例。

1. 进入“预设管理”，刷新列表，选 **维维美_轻元气_090**，点“应用”；也可在音频生成页“从预设加载”。
2. 查看参考音频已经加载，情感方式为向量；开心 0.30、惊喜 0.05、权重 0.65、随机关闭。
3. **手动把语言设为 ZH，时长系数设为 0.90。** 官方预设目前不恢复语言、时长系数、稿件或种子。
4. 把一个场景的完整 say 文本复制进文本框，点“生成语音”。不要按字幕行一次只放几个字。
5. 先听有没有读对，再听语气。下载保留自己喜欢的 WAV；记录文字和参数，不要只凭文件名猜设置。
6. 想做对比时保留基准版本，再只改一个值。例如同一句对比 0.90 / 0.93；其余参数保持原样。
7. 自己的新实验用另一个预设名，例如“维维美_实验_开心035”。完整的已认可 profile 和试听原件仍保留。

UI 没有暴露本脚本的固定种子，因此界面同参数重复生成可能有细节差异。你要严格按这次完整配置复用时，让我用脚本即可。

## 6. 建议的试听顺序

| 顺序 | 你改什么 | 先试多少 | 什么时候才继续改 |
| --- | --- | --- | --- |
| 1 | 台词 | 一次只改一个场景 | 意思正确、口语顺畅 |
| 2 | 标点 | 同一句两个版本 | 自然、清楚，不靠刻意空白 |
| 3 | 速度 | 0.90 与 0.93 | 仍觉得太急时；0.93 会稍慢 |
| 4 | 开心 | 0.30 与 0.35 | 仍觉得不够活泼时 |
| 5 | 情感权重 | 0.65 与 0.70 | 想增强既定情绪时 |

这些是小幅实验起点，不是必须调整的标准。当前认可的 0.90 档优先使用。不要同一次把速度、开心、权重、参考音频都换掉。temperature、top_p、top_k、num_beams 等高级生成项先保持已存值，只有出现具体问题时再排查。

## 7. 把审核稿接回视频

最简单：把改好的文字或你喜欢的 WAV 发给我，我核对版本、替换音轨、测量时长、更新画面和字幕。

自己运行时，进入 video 文件夹，给每一版一个新的批次名：

```powershell
Set-Location -LiteralPath 'C:\codex project\codex pet\video'
powershell -NoProfile -File .\scripts\make-index-voiceover.ps1 -BatchName my-edit-v2
npm run sync-voiceover
npm run dev
```

合成使用 D:\Anaconda\envs\index-tts；官方权重仍在 C:\IndexTTS。中央原始音频、参数在 C:\IndexTTS\outputs\weiweimei\pet-intro\批次名；视频里的音轨副本在 public/voiceover/批次名。旧批次不会覆盖。

场景时长来自新 WAV；字幕内部时间初步按文本长度分配，需要试听后在 Studio 修正。字幕编辑写回 src/speech.tsx，再运行 sync-voiceover 会重生成它：先保存手工修改，或让我把修正写回 voiceover-timing.json。声音与稿件审核通过后再导出定稿。
